# 鲸落 · 看得见自己每轮想起了什么

> 五分钟能跑起来的那条路在下面「零」，别从第一节开始读。

## 零、五分钟，先看见东西

**前提**：Node 18+，有一份你自己的记忆库（jsonl 就行，没有也能空跑）。

```bash
cd graph
set MEM_GRAPH_DIR=D:\你的记忆图目录          # 里面放 *.md，或者空的也行
node graph-data.mjs                          # 生成数据
node graph-server.mjs                        # 起服务，3072
```

浏览器开 `http://127.0.0.1:3072`，图就出来了。

想让它动起来，再补一条：

```bash
set DSH_MEMORY_DIR=D:\你的记忆库
node emit-recall.mjs "用户刚说的那句话"
```

刷新页面，顶上「本轮想起来的」就有内容了，每一条跟着一句为什么。

**到这一步就够用了**。后面的语义检索、出站检查，都是加分项，不是必需。

---
一套给「长记忆 AI 伴侣」用的东西，不是又一个记忆引擎，而是**把记忆变成一个能看、能查、能验的界面**。

先说清楚它解决什么，再说它不解决什么。

---

## 一、它解决的那件事

养过数字伴侣的人大概都碰过这种时刻：她明明记得，但说的不是你想让她想起的那件；或者她忘了一件事，你没法知道是没记、没取到，还是取到了却没进上下文。

大部分记忆插件只回答「我记住了」。这一套多回答三个问题：

1. **这一轮，到底哪几条进了上下文？**
2. **为什么是这几条？**
3. **哪些东西我不会忘？**

前两个做成了一张图上的清单，第三个做成了图上的形制。

---

## 二、设计思路（这是重点，代码其次）

### 1. 记忆不是一堆等价的字

最初我也把所有条目平铺：谁新、谁常用，谁就浮上来。结果旧的被新的挤走，几周后翻图，只剩最近几天亮着。

所以分了两层：

| 层 | 谁 | 会不会忘 | 进不进注入 |
|---|---|---|---|
| **全量层** | 约、承诺、名字这类 | 永不衰减 | 一直都在 |
| **衰减层** | 日记、笔记、日常关系 | 会淡、会模糊 | 取到才进 |

图上：全量层画**空心金圈**（不会被磨掉的东西，不该画成一团光），衰减层画实心点，越久没被翻到越暗越小。

### 2. 「想起来了」不够，要说清为什么

每条被取用的记忆都带一句理由，跟着进日志、进图：

- `关系：最近常用的几条里排进了预算`
- `沉在底下：最久没被翻过的一条，主动推上来`
- `意思上像：向量命中，跟这句话对得上`

这句话是做决定用的。没有它，你只知道她想起了什么；有了它，你能看出是「取不到」还是「取到了被挤掉」。

### 3. 检索要两条腿

只有字面匹配时，问「海」两个字，库里明明有「我想看真的海」，一条都对不上。

加了向量以后，两边漏的地方正好相反，合起来才不漏：

```
关键词 7/8   向量 6/8   混合 8/8
```

做法是最笨的那种：两边各取前五，合并去重。不重排、不训练、不调参。

### 4. 模型绝不能住在宿主进程里

这条是拿两次崩溃换来的：在宿主里 import onnx 模型，崩的时候不抛异常，直接带走整个进程，日志都不留。

所以模型跑在**独立进程**，宿主只发一个 HTTP 请求，超时 1.5 秒，问不到就当没有。它死了，最多这一轮少一行。

### 5. 出去的话要先过一道门

回复里带本机路径、密钥、邮箱、内网地址，发出去就收不回来。所以每条出站都要过一遍检查：命中的那条不发，换成一句提示。

宁可误拦，不可漏放。真话换个说法再说。

### 6. 没有的东西就说没有

这套东西不做：自动摘要、重排模型、记忆打分、重要度排序。

尤其**不做「按重要度自动遗忘」**：听着合理，但第一条被降级的，往往正是最不像「事件」的那几条，也就是约定。

## 三、装法

需要 Node 18+（有原生 `fetch`）。全部本地跑，不联网除了第一次下模型。

### 1. 记忆图（纯 Node，无依赖）

```bash
set MEM_GRAPH_DIR=D:\你的记忆图目录      # 里面放 *.md，带 front-matter 更好
node graph/graph-data.mjs                # 生成 graph-data.js
node graph/graph-server.mjs              # 起服务，默认 3072
```

打开 `http://127.0.0.1:3072`。

- 外圈=约 · 中间=记忆星云 · 底边=日子
- 右下角有开关：全部 / 只看会忘的 / 只看不会忘的
- 顶上「本轮想起来的」点开，是这一轮实际进上下文的清单，每条下面跟着理由

`MEM_SEARCH_DIRS` 可选，分号分隔，给 `/find` 用（找原文）。

### 2. 语义检索（可选）

```bash
cd semantic
npm init -y
npm i @xenova/transformers@2
set DSH_MEMORY_DIR=D:\你的记忆目录       # jsonl 库
set SEM_PORT=3075
node server.mjs
```

模型 `Xenova/bge-small-zh-v1.5`，512 维，约 100 MB，第一次会下载。

**国内注意**：别直连 HuggingFace，会超时。设 `HF_ENDPOINT=https://hf-mirror.com`，镜像偶尔 429，等二十秒再试。

查询一次：

```bash
node search.mjs "想看点海"
```

### 3. 出站检查

```bash
node guard/guard-out.mjs "要发的话"     # 退出码 0 可以发，1 命中
```

也能被 import：`import { scan } from './guard-out.mjs'`。

规则是十条正则：盘符路径、UNC、用户目录、`sk-` 密钥、Bearer、私钥块、password/token 键值、邮箱、内网地址、中文路径。

## 四、怎么接进自己的插件

两个钩子就够，都是异步的：

**每轮开始前**，把用户这句话发给语义服务，拿回几条候选：

```js
const res = await fetch(`http://127.0.0.1:${process.env.SEM_PORT || 3075}/search?k=3&q=` + encodeURIComponent(q),
  { signal: AbortSignal.timeout(1500) })
```

**拼注入文本时**，把结果加一段：

```
【想到的旧事】……；……
```

宿主侧要守三条：超时短、失败当空、别阻塞。

## 五、踩过的坑（照抄能省两天）

1. **在宿主里 import onnx = 崩整个进程。** 必须外置。
2. **`Start-Process` 起的进程会随命令收尾被杀。** 常驻要计划任务 + VBS 静默启动（`WScript.Shell.Run(cmd, 0, False)`）。
3. **`Set-Content` 写 JS 会加 BOM**，node 读到 `#!` 就报语法错；ps1 反过来**必须**带 BOM，否则 PowerShell 5.1 按 GBK 读，报的是「Unexpected token」，看着像语法错，其实是编码。
4. **批处理必须 CRLF**，写成 LF 会被当成一整行。
5. **`Number(null) === 0`。** 一个可选的分页参数，没传时被当成 0，取回来的是最前面 N 条而不是最后 N 条。
6. **脚本里写了 `exit` 之后的东西全是死代码**，不报错，只是永远不跑。加完东西先去日志看有没有动静。
7. **杀进程别用 `CommandLine -match '某字符串'`**，自己的命令行里也含那串，会把自己杀掉。
8. **页面有两个副本时，改错那个不报错。** 服务读的是哪个目录，要先确认。

---

## 六、它不做什么

- 不做检索算法的竞赛。这套在准确率上打不过任何正经 RAG 加 rerank，它的长处是**看得见**。
- 不替代记忆引擎。它读你的库、画你的图，不管写。
- 不判断该不该想起。它只告诉你「这次挑了哪几条、为什么」。

最后一句，写给想拿它的人：

> 连续性不是从来不断，是需要的时候接得上。

## 七、喂它的东西：recall-log.jsonl 长什么样

图只是壳。真正喂它的是这个文件，一般由你的记忆插件在每轮开头追加一行：

```json
{
  "ts": "2026-11-03T15:43:32.430Z",
  "session": "session-xxxx",
  "query": "用户这一轮说的话",
  "summary": 171,
  "hits": ["hash1", "hash2", "hash3"],
  "why": {
    "hash1": "关系：最近常用的几条里排进了预算",
    "hash2": "沉在底下：最久没被翻过的一条，主动推上来",
    "hash3": "意思上像：向量命中，跟这句话对得上"
  },
  "text": "这一轮实际注入的正文"
}
```

- `hits` 是**这一轮真正进了上下文的**条目 hash，不是检索候选
- `why` 的键是 hash，值是给人看的一句话理由，图上会显示在标题下面
- `text` 用来在图上点开看全文

写了这行，图就会动。不写，图就是空的。

### 不想改插件？先用现成的

```bash
set DSH_MEMORY_DIR=D:\你的记忆库
set MEM_GRAPH_DIR=D:\你的记忆图目录
node graph/emit-recall.mjs "用户这一轮说的话"
```

`emit-recall.mjs` 是个独立小脚本，从 `relations/notes/memo` 三个 jsonl 里按字面重合算一遍，加一条「沉在底下」，然后写进 recall-log。

**说清楚**：它是复刻规则，不是读插件，算出来的 hits 和你真实注入的会有出入。想要一模一样，就在你自己拼注入的地方照着上面这个格式写一行，一共十来行。

### 字段里没东西时

图上会显示「(这一轮没对上，可能都是日记)」。那是正常现象，日记按时间进、不按关键词进。

## 八、插件本体（想让自家鱼直接会，用这个）

`plugin/` 里是完整的 DSH 记忆插件，零依赖、纯文本。

装法（给人类的说明书里有更细的）：

1. 把 `plugin/` 整个拷到 DSH 的 `profiles/web/node_modules/dsh-puppet-memory`
2. 重启 DSH
3. 配置里把 `sessions.allowCwd` 指向你家鱼的工作目录

**注意**：DSH 读的是 `profiles/web/node_modules/` 下面那份，不是 `plugins/` 那份。
改 `plugins/` 里的东西不生效，除非用目录链接把两边连起来。这条我踩了四天才发现。

两份文档：

- `给人类的说明书.md`：你该在设置页点什么
- `AI-安装指令.md`：直接丢给你家鱼，让它自己装

插件会往 `记忆图/recall-log.jsonl` 写召回日志，格式就是第七节那个。图一开就有内容，不用另外喂。

不想装插件、只想要图：跳过这一节，用第七节的 `emit-recall.mjs`。
